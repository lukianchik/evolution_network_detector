# Исследовательский отчёт v1.0.0

## Постановка

Цель — уменьшить число ложных тревог на сетевых потоках, сохранив достаточную полноту и интерпретируемое правило. Ориентиры на итоговом наборе UNSW-NB15 — F1 ≥ 0.90, FPR ≤ 0.10, recall ≥ 0.90. Local работает без API и GPU. Эксперименты выполнены на Ryzen 7 5700X, 16 GiB RAM и Python 3.12.

## Метод и протокол

Local и Hybrid используют общее ядро. Оно строит пороги из train, автоматически распределяет попытки между пятью стратегиями, оценивает до четырёх локальных кандидатов на validation за поколение и выбирает лидера из ограниченного Pareto-архива по заранее заданному профилю. Схема правил допускает веса, интервалы, вложенные группы и отрицание. Ошибки классификации агрегируются на train, без сырых потоков в запросах Groq. MCP сверяет матрицы ошибок и идентификатор выборки на контрольных точках. [Алгоритм и параметры](algorithm.md)

Основное сравнение использовало seed 42–46, профиль balanced, потолок 12 × 15 локальных попыток, нулевой LLM-бюджет и отключённый MCP, чтобы измерить поиск. Конфигурации и лидеры фиксировались до финальной оценки. Абляции сравнивались на общем внутреннем validation и не отбирались по test.

Доля атак меняется с 68,06% до 55,06%. Из 82 332 test-строк 19 655 имеют одинаковый вектор признаков хотя бы с одной train-строкой. Наибольшие одномерные расстояния Колмогорова–Смирнова наблюдаются для `sinpkt` (0,113), `ct_dst_src_ltm` (0,104) и `ackdat` (0,097). В проверенных признаках этих CSV пропусков нет. Машиночитаемый аудит содержит распределения протоколов, состояний, сервисов, категорий атак, квантили и число выбросов по IQR там, где IQR больше нуля. Группировка предотвращает попадание точно одинаковых векторов официального train в разные части внутри обучающего набора. В CSV отсутствуют надёжные ключи хоста, временного окна и сессии. Группа использует страту первой строки, если её метки конфликтуют. Фактические размеры из-за целых групп составили 9 221, 19 594, 49 910 и 166 658 для целей 10k, 20k, 50k и полного доступного train. Общий validation содержит 4 484 строки, резерв — 4 199. Схема исключает `id`, `label` и `attack_cat` из входа правила. Категория нужна для стратификации и разрезов.

## Основные результаты

Среднее ± выборочное SD по пяти запускам, кроме исходного правила.

| Детектор и раздел | F1 | FPR | Recall | Precision |
|---|---:|---:|---:|---:|
| Исходный Seed · официальный test | 0.3548 | 0.0334 | 0.2216 | 0.8904 |
| Local · validation | 0.9277 ± 0.0078 | 0.1134 ± 0.0147 | 0.9060 ± 0.0108 | 0.9505 ± 0.0064 |
| Local · официальный test | 0.8604 ± 0.0110 | 0.2398 ± 0.0244 | 0.9026 ± 0.0131 | 0.8220 ± 0.0154 |
| Local · внутренний резерв | 0.9089 ± 0.0167 | 0.1188 ± 0.0205 | 0.8752 ± 0.0239 | 0.9454 ± 0.0099 |


Четыре seed из пяти достигли recall ≥ 0.90 на test. Ни один из пяти не достиг F1 ≥ 0.90 или FPR ≤ 0.10. По сравнению с внутренним validation FPR на официальном test выше на 12,64 пункта. На test полнота обнаружения Fuzzers варьируется от 0.524 до 0.722, Generic — от 0.992 до 0.994. По категории Worms в test всего 44 записи. По категориям приведены recall для атак и FPR для Normal в артефактах, поскольку разрезы по виду атаки содержат только положительные примеры.

Hybrid с нулевым бюджетом воспроизвёл лидеров и validation-метрики Local по всем seed. Это проверяет равенство общего ядра. Реальный вклад Groq в качество пока неизвестен. ShinkaEvolve 0.0.8 прошёл сквозной запуск на Synthetic через локальный HTTP-шлюз с подменой Groq SDK, включая оценку нового потомка. Подтверждение работы с живым Groq требует отдельного запуска с разрешённым бюджетом. [Маршрутизация Shinka через OpenAI-совместимый endpoint](https://github.com/SakanaAI/ShinkaEvolve/blob/main/docs/support_local_models.md) · [Совместимость Groq](https://console.groq.com/docs/openai)

## Абляции на validation

Пять seed на вариант. Параметры поиска и потолки бюджета общие. Ранняя остановка и разная стоимость стратегий влияют на фактический бюджет.

| Вариант | F1, среднее ± SD | FPR, среднее ± SD | Recall, среднее | Фактических попыток, среднее |
|---|---:|---:|---:|---:|
| Unified, ~20k | 0.9277 ± 0.0078 | 0.1134 ± 0.0147 | 0.9060 | 180 |
| Ограниченный набор из 11 признаков | 0.9321 ± 0.0061 | 0.1071 ± 0.0440 | 0.9118 | 171 |
| ~10k | 0.9062 ± 0.0137 | 0.1080 ± 0.0153 | 0.8661 | 162 |
| ~50k | 0.9228 ± 0.0147 | 0.1313 ± 0.0201 | 0.9039 | 168 |
| Полный доступный train | 0.9138 ± 0.0122 | 0.1196 ± 0.0119 | 0.8834 | 171 |
| Без Error-driven | 0.8701 ± 0.0506 | 0.1193 ± 0.0495 | 0.8128 | 144 |
| Циклический координатор | 0.9145 ± 0.0188 | 0.1179 ± 0.0187 | 0.8845 | 162 |
| Скалярный отбор | 0.9584 ± 0.0017 | 0.2015 ± 0.0077 | 0.9972 | 174 |
| Без кэша | 0.9277 ± 0.0078 | 0.1134 ± 0.0147 | 0.9060 | 180 |

Координатор и Error-driven дали более высокий F1 и recall в этом протоколе. Разницу между Pareto и скалярным сравнением нужно читать вместе с разницей целевых функций. Скалярный вариант чаще метит поток как атаку. Вклад расширения признаков в качество остаётся неопределённым. На внутренней выборке ограниченный набор признаков немного впереди по средним метрикам, с большим разбросом FPR. Рост train до ~50k и до полного доступного набора не дал монотонного улучшения при том же потолке попыток.


## Вычислительная эффективность

При лимите 180 попыток Unified в среднем выполнил 1 533 полных train-оценки, 794 проверки простых условий и 3 672 агрегированных оценки ошибок, до 49 validation-оценок с seed. Полная оценка и подсчёт пересечений масок имеют разную стоимость. Средняя сложность лидера — 5,4 узла. Local и Hybrid с нулевым бюджетом не расходуют токены.

В последовательной серии из пяти seed время составило 3,99 ± 0,34 с wall, средний пиковый RSS — 317,66 MiB. Без кэша масок wall составил 3,93 ± 0,36 с при тех же правилах. Среднее время внутри движка после подготовки — 0,67 с с кэшем и 0,74 с без кэша. Разница мала относительно разброса общей длительности.

## Ограничения и воспроизведение

Официальный test ранее анализировался при разработке и содержит точные совпадения признаков с train. Внутренний резерв отделён от поиска, но происходит из того же обучающего CSV. Ранее не использованный независимый захват недоступен. Для отдельного размеченного захвата предусмотрен `python -m evaluation.final_test --run results/unsw-experiment --control-csv path/to/holdout.csv`. Лабораторная разметка, зависимые потоки, редкие классы и доступность признаков в коллекторах ограничивают переносимость результатов.

```sh
python -m tools.benchmark --dataset unsw --modes local --seeds 42 43 44 45 46 --final --output results/research-frozen-repro
python -m tools.benchmark --dataset unsw --modes local --variants unified legacy-features train-10000 train-50000 full-train no-error no-adaptive scalar no-cache --seeds 42 43 44 45 46 --workers 3 --output results/research-ablation-repro
python -m tools.audit_data --include-test --output results/research-data-audit-repro.json
```
