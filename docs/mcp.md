# MCP-метрики

`python -m integrations.mcp_metrics` запускает stdio-сервер. В Compose worker обращается к `http://metrics:8090/mcp` по Streamable HTTP. У сервера собственный кэш оценщиков и доступ к копии официального train. Groq-ключей и test CSV в контейнере metrics нет.

| Инструмент | Что возвращает |
|---|---|
| `evaluate_rule` | Метрики правила, сложность и идентификатор выборки |
| `compare_rules` | Матрицы ошибок двух правил и разницу F1, FPR и fitness |
| `get_best_rule` | Зафиксированного лидера и структурированное правило |
| `get_search_summary` | Число оценок, ID лидера, фронт и счётчики стратегий |

Для сравнения правил на UNSW передаются `dataset="unsw"`, `train_size=20000`, `validation_size=4096`, `feature_set="expanded"` и `fpr_penalty`. Если `train_size` отсутствует, сохраняется прежняя небольшая выборка UNSW для старых MCP-клиентов. Допустимы только разделы `train` и `validation`. При несовпадении матриц ошибок или идентификатора выборки движок регистрирует ошибку. После двух сбоев он прекращает MCP-вызовы до конца запуска, сохраняя локальный результат.

Проверки:

```sh
python -m pip install -r requirements-mcp.txt
python -m tools.mcp_smoke
docker compose exec -T worker python -m tools.mcp_smoke
python -m tools.docker_smoke
```

Последняя команда создаёт запуск через веб-прокси и проверяет реальные подтверждения поколений. Стандартный stdio-клиент открывает дочерний процесс для каждого сеанса. Для длительных UNSW-серий HTTP-сервис переиспользует подготовленные данные. Для измерения собственно CPU-поиска используется `--no-mcp`.
